# Final Architectural Improvements Plan

## Background & Motivation
The user requested that we address all the suggestions generated by the codebase investigator. These improvements tackle technical debt, performance risks, and potential production deployment issues.

## Scope & Impact
1.  **Strict Environment Variables**: The `api.ts` file currently falls back to `localhost:3000` or a dummy URL if `EXPO_PUBLIC_API_URL` is missing. This is a severe production risk. We will make it fail loudly.
2.  **Optimize Zustand Persistence**: The `marketplaceStore` and `userStore` currently persist massive lists of data (like `listings` and `properties` and `holdings`) to `AsyncStorage`. This slows down app startup as the database grows. We will use Zustand's `partialize` to only persist lightweight, essential state (e.g., viewMode, favorites).
3.  **Component Modularity**: The `marketplace.tsx` file has an inline implementation of a property card that is over 100 lines long. We will refactor it to use the `PropertyCard` component located in `src/components/ui/PropertyCard.tsx`.

**Affected Files:**
-   `mobile/src/config/api.ts`
-   `mobile/src/stores/marketplaceStore.ts`
-   `mobile/src/stores/userStore.ts`
-   `mobile/app/marketplace.tsx`

## Proposed Solution & Implementation Steps
1.  **Strict Environment Variables**:
    *   In `mobile/src/config/api.ts`, remove the `localhost` and `app.json` fallbacks in `getBaseUrl()`.
    *   Throw a descriptive `Error` if `process.env.EXPO_PUBLIC_API_URL` is undefined.
2.  **Optimize Zustand Persistence**:
    *   In `mobile/src/stores/marketplaceStore.ts`, add the `partialize` configuration to the `persist` middleware, ensuring only `favorites` and `viewMode` are persisted.
    *   In `mobile/src/stores/userStore.ts`, add the `partialize` configuration to ensure only `profile`, `investorPreferences`, `farmerPreferences`, and `isProfileComplete` are persisted (omitting `wallet` and `holdings` arrays).
3.  **Component Modularity**:
    *   In `mobile/app/marketplace.tsx`, locate the `renderItem` method for the `FlatList`.
    *   Replace the inline `TouchableOpacity` and nested `View` components with the `<PropertyCard />` component imported from `../src/components/ui/PropertyCard`.

## Verification
-   The app should throw a clear error if `EXPO_PUBLIC_API_URL` is not provided during the build.
-   The marketplace screen should successfully render the exact same UI but utilizing the modular `PropertyCard` component.
-   Closing and reopening the app should no longer flash stale listing data that was previously improperly persisted to `AsyncStorage`.
